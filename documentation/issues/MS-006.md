# MS-006 — Revision Animation : lecture timeline bibliothèque et fichiers Vue

Statut : En revue. Responsable : coordinateur. Dépendances : MS-005. Références : ../ARCHITECTURE.md, ../DESIGN.md, ../../README.md.

Résultat : lecture/pause/seek/boucle/vitesse, bibliothèque en mémoire, import/export JSON et personnage GLB avec contrôles typés. Les pistes restent une visualisation de poses, pas un éditeur.

Critères : commandes testées RED/GREEN, wrappers de contrôles réutilisés, erreurs de fichiers affichées, incompatibilité de rig refusée, limites 20/30 Mo préservées, interface d’export futur conservée. Aucun export GLTF d’animation ajouté.

Recette navigateur : capturer, arrêter, lire, pause, seek, boucle, vitesse, exporter puis réimporter et comparer durée/poses. GLB production et téléphone restent des essais distincts.

Réalisation : AnimationTimeline, AnimationLibrary et AnimationFilesPanel composent les primitives Vue. Les pistes sont dessinées par un adaptateur canvas. Les fichiers sont lus/téléchargés dans infrastructure/files ; SHA-256 et bornes 20/30 Mo sont préservés. Le port AnimationExportAdapter reste hors du domaine, sans export GLTF implémenté.

Preuves : commandes testées dans la boucle RED/GREEN de MS-005 ; quatre caractérisations de fichiers (bornes avant lecture, JSON invalide, identification SHA-256). Au navigateur : clip « Recette_Vue3 », 8,21 s et 11 poses dans l’onglet secondaire contraint ; lecture/pause, seek à 2,00 s, boucle désactivée et vitesse 2× ; export JSON puis import du même fichier, mêmes durée et nombre de poses. Un second essai dans l’onglet actif donne 905 poses pour 30,13 s (MS-007). Ces résultats ne garantissent pas le débit sur téléphone.

Reste : recette d’un GLB de production compatible et acceptation PO des parcours. Les refus de rig sont automatisés ; aucune compatibilité universelle n’est revendiquée.
