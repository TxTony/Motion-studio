# MS-009 — Fix Capture: align the overlay and reuse the classic coach profile

Status **In review**. Owner **Coordinator**. Follow-up to [MS-004](MS-004.md).

## Scope and evidence

The PO reports a persistent overlay offset while stationary and unstable tracking with only the upper body visible. On 27 November 2026 the PO identified the classic coach as the working reference. Source comparison against [posture-coach-demo/index.html](https://github.com/TxTony/posture-coach-demo/blob/a65fba21ce92e81085c59f4f34e1cdd1367b85cd/index.html) confirms the same Lite v1 model, GPU with CPU fallback, 90 ms inference spacing, 0.55 detection/presence/visibility thresholds, and portrait 720 × 960 / 24 FPS camera preferences. Motion Studio currently uses CPU, a 30 Hz inference cap, and 640 × 480 preferences.

The coach draws in native video coordinates and lets identical CSS object-fit/centering fit both surfaces. The current studio manually fits coordinates into a viewport-sized backing store. Static reading has not proven the cause of the reported offset. Reusing the coach's single coordinate space removes that extra projection. No reference artifact or character geometry changes.

## Contract and acceptance

Keep PoseSample, camera lifecycle/cancellation, JSON, and retargeting contracts unchanged. Use native video dimensions for the overlay and shared contain/center/mirror CSS. Redraw when metadata or the source changes. Adopt the classic detection profile with GPU initialization followed by CPU fallback; retain the installed MediaPipe SDK rather than downgrade dependencies. Portrait constraints are preferences, not a promise of a wider field of view. Missing legs and 3D depth remain estimated.

Exclusive files: capture adapter, skeleton overlay adapter, capture viewer, capture CSS, their focused tests, README, architecture, and project tracking. TDD covers GPU/fallback failures, profile cadence/constraints, native-coordinate drawing, uncertain points, and source/metadata updates. Run the full check and a camera-free browser rendering check. Human acceptance must compare stationary visible shoulders/head and slow motion on the PO's camera; hardware quality cannot be established by mocks. Rollback is this issue's commit only.
