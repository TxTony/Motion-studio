# MS-005 — Revision Animation: session commands and Vue recording

Status **In review**. Session owner **`animation_domain`** (`gpt-6.2-sol`, `medium` effort). The coordinator integrates the composable and the view. Depends on MS-002 and MS-004. See the [architecture](../ARCHITECTURE.md) and [design](../DESIGN.md).

The session exposes commands for the demo and camera sources, camera start and cancellation, the current pose, settings, recording and stop, unavailable actions, and errors. The Vue composable assembles these commands and delegates rules to the session.

Acceptance criteria include RED/GREEN tests for transitions and recording with fake ports and a controlled clock, correct placement of form fields and selectors, and reuse of `StudioButton`. Each studio owns its own session and keeps engine objects outside deep Vue reactivity.

Capture acceptance covers recording from Demo, blocking conflicting actions, stopping, and finding the clip. It verifies cleanup at unmount and when entering the background. The five-minute limit is preserved.

## Session contracts

- `StudioSession` owns the player, recorder, mode, source, and library. It receives the runtime and monotonic clock by injection. The snapshot is shallow, and the clip list is replaced whenever a clip is added. The demo clip is selected at startup while the studio is in live mode.
- `tick` and the clock use milliseconds. Smoothing, the timeline, and recorded duration use seconds. `rewind()` preserves active playback. `seek()` pauses it.
- Cancelling a camera request invalidates its generation. A late response leaves a newer request's status and lock intact. `undefined` keeps the displayed skeleton. `null` clears it, and tracking loss prevents recording after more than 750 ms without a pose.
- Loading a GLB holds an operation slot until it resolves. Successful loading clears the selection and updates the character name. The library retains clips for all rigs, and playback requires the matching rig.
- The composable can publish an export confirmation with `reportInfo()`. It replaces an active error status. Notifications after disposal are ignored.
